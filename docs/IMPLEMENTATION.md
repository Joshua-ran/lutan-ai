## 技术选择

React 19 + TypeScript + Vite 提供移动端优先 H5；Express 5 提供无状态接口；Zod 4 验证输入、输出及本机存储格式。

PRD 中的 FastAPI 是拟议实现。本版选用 Node，是为了使前后端直接复用同一个 TypeScript 规则模块，在 API 降级时保持结果一致。数据对象与规则版本独立于服务框架，后续如需 Python 服务可按相同契约迁移。

V1.1 已增加服务端兼容模型适配器、规则风险门控、输入脱敏、结构化输出校验和失败回退。默认无密钥时 `llm: false`；完整配置且显式启用后 `capabilities.llm: true`，只表示配置通过，不表示真实供应商已联通。天气、水位、物种及云存储仍为 `false`。协议、配置、候选生成边界与未验证范围见 [AI 工作流](AI_WORKFLOW.md)。

## 数据流与状态

```text
前端输入 → 去除水域备注 → API 输入校验 → 共用规则风险门控
                                            ↓ 普通且自述合法、已配置
                                      模型选择可信候选 → 严格输出校验
                                            ↓ 失败
                                        原规则结果回退
                         ↓ 网络或接口异常
                    共用本机规则（页面明确标注）

返回结果 → 恢复仅留本机的备注 → 输入快照 + 结果反馈 → localStorage
                                                      ↓
                                            查看 / 筛选 / 导出 / 删除
```

前后端均从 `shared/engine.ts` 调用规则，规则版本 `lutan-rules-1.0.0`。Zod 严格拒绝未声明字段；原始输入发生改变会中止在途请求并移除旧建议，避免结果与输入错配。接口请求最长等待 4.5 秒后降级；响应格式或版本校验失败同样降级。

不发送水域备注给接口。服务不持久化会话、反馈或请求正文，也没有云记录。匿名结构化条件会发送到本机服务用于本次计算。默认服务仅监听 `127.0.0.1`。

本机键仍为 `lutan_records_v1`，值接受 V1/V2，成功写入与导出使用 `schema_version: 2`，最多 500 条记录。旧记录在内存中补齐规则来源元数据，读取时不重写，后续成功修改时升级 V2；不补造历史模型信息。同一次诊断以诊断 ID 为键更新反馈，新诊断使用独立 ID。读取和写入均校验结构，损坏记录保留原文供备份，写入/删除失败不宣称成功。旧单文件原型使用的 `lutan_v1_records` 不自动覆盖或迁移，避免缺字段时虚构历史输入。

页面导航保留当前会话；刷新会重新开始未保存的计划。已保存记录可刷新保留，仍取决于浏览器允许 localStorage。开发与生产端口是不同来源，记录相互独立。

## 规则优先级

1. 明显急涨水或明显急流 → 先撤离危险岸边，核对官方预警。
2. 用户报告禁止垂钓 → 停止作钓。
3. 合法性未知 → 在安全位置先核对官方公告，确认前暂停作钓。
4. 有跟饵 → 保持其他变量，只验证回收节奏。
5. 疑似触碰 → 检查钩尖钓组，区分结构碰撞。
6. 拟饵缺失 / 搜索水层不明 → 最多一项关键追问，先确认覆盖路径。
7. 多种拟饵、多个水层、手法换位都试过且长时间无口 → 考虑结束标点搜索。
8. 多变量已试但时长短或未知 → 固定条件完成一次比较，不机械建议放弃。
9. 尚未换位 / 只搜索一层 / 换位后仍无口 → 选择尚未单独比较的一个变量。

用户自述已核实允许不等于系统独立核验许可，普通建议也不代表现场安全保证。退水、雨后、水色变化以用户观察描述，不能推导通用因果或鱼口概率；炸水与跟饵不直接识别鱼种。

## 接口

| 方法 | 路径             | 内容                                                 |
| ---- | ---------------- | ---------------------------------------------------- |
| GET  | `/api/health`    | 服务、规则版本与真实能力状态                         |
| POST | `/api/pretrip`   | 出钓参考卡，允许缺省观察项                           |
| POST | `/api/diagnoses` | 输入快照、单项建议、依据、未知项、风险、最多一个追问 |

请求与响应均为 JSON。正文上限 16 KB；错误 JSON 返回 400，过大请求 413，字段校验失败 422，不存在接口 404。响应不缓存，不暴露内部堆栈。

出钓请求示例：

```json
{
  "water": "河流 / 支流",
  "fish": "鳜鱼",
  "waterlevel": "未知",
  "rain": "未知",
  "legality": "未知"
}
```

现场诊断在此基础上接受 `structure`、`duration`、`lures[]`、`layers`、`adjust`、`signal`、`flow`、`clarity`、`observed`。完整枚举见 `shared/schema.ts`，未知观测默认为“未知/不清楚”，拟饵默认为空数组，不假定用户已尝试动作。

## 评测的实际口径

`npm run evaluate` 读取原始场景并逐条保存输出、规则版本、断言结果、归一化假设和原始检查点。现场场景为隔离诊断分支，显式补齐“用户已核实允许”和默认软饵；原始输入仍保留。合法性未知、禁钓和危险优先级由独立测试与 UI 测试覆盖。

初次自动检查：23 PASS、0 FAIL、1 NEEDS_REVIEW。P02 的历史物种来源、年份和假设展示属于 P1，未接入。测试中验证该场景仍为待复核，因此“测试套件通过”不意味着“24 个产品场景全部通过”。所有逐条 `human_review` 都为 `pending`，不替代原始方案要求的人工判分。

浏览器流程覆盖桌面 1440×1000 与手机 390×844：首屏、输入复用、单项建议、危险提醒、旧结果失效、在途请求取消、API 降级、反馈保存、刷新保留、导出和删除。当前使用本机 Chrome；尚未验证真实 iOS Safari、低端设备或真实钓友使用。

V1.0 基线验证记录：生产构建成功，39 项规则、接口、存储测试通过；18 项桌面/手机浏览器测试通过。该记录是上一轮本机执行结果，不代表外部审查环境独立重跑成功。

V1.1 本轮执行：65 项规则、接口、模型适配和存储测试通过；26 项桌面/手机浏览器测试通过。新增 AI 测试使用本机模拟供应商，包括真实本机 HTTP 调用链；不是对真实付费模型的效果测试。场景评测仍为 23 PASS / 0 FAIL / 1 NEEDS_REVIEW，P02 未接入且人工评估仍待执行。
